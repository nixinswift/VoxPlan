# Project rules
- Personal practice projects are registered in a private owner registry on creation, with restrictive write policies on project data; renaming a project cannot bypass protection, and existing account-approval policies still apply.
- Share civil-earthworks evidence and fleet-production guidance across drawing, estimating and scheduling entrypoints; store civil non-concrete lines in building discipline, with m3/t fractional per-occurrence quantities in length and an integer occurrence count so existing costing/export storage remains compatible.
- Project deletion must return exactly the requested deleted ID before confirming success; database policies allow administrators to delete non-demo projects while retaining the restrictive account-approval gate.
- Share heavy-industrial mechanical domain guidance under the edge functions' `_shared` directory across AI entrypoints, so scheduling and takeoff use consistent dependencies and evidence standards.
- Store mechanical non-concrete takeoff lines within the existing building discipline using the mechanical trade, so quantity, costing and export flows remain compatible without a separate storage model.
- Share technical drawing evidence rules across extraction, takeoff and schedule upload; stage drawing takeoffs for review and retain source evidence in descriptions and schedule notes so it survives reloads without a separate metadata schema.
- Main estimator drawing uploads use a multi-discipline reader and parse both concrete and building tool results before review, so non-concrete drawings are never rejected by a concrete-only path.
- Normalize concrete volumes to cubic metres through the shared quantity helper before totals, costing and exports; entered dimensions retain their unit, so mixed-unit totals cannot silently mix cubic feet and metres.
- Keep estimator and schedule drawing file-size validation in a shared module, so their limits stay consistent.
- Prepare large PDFs client-side with lossless page copying and sequential analysis parts to avoid base64 request memory exhaustion while retaining readable engineering callouts.
- Store drawing-derived cost proposals separately from schedule and takeoff; use shared deterministic productivity and quote calculations, and substitute reviewed proposals for schedule allowances only after explicit approval to avoid double-counting.
- Cost planner must process bounded sequential takeoff batches with full-scope deduplication context, project-wide equipment only once, and atomic proposal assembly; skip incremental JSON parsing while retaining strict schema and final validation to stay within edge CPU limits.
- Seed per-user editable demo projects from a private-schema signup trigger on auth.users that swallows its own errors, so onboarding data never blocks registration.
- Resource diagnostics, Costs and exports share equipment identity parsing and severity scoring, with count prefixes such as "1 crane C1" normalized to the unit name so one unit never splits into separate identities; booking identities remain task IDs so equal names cannot hide demand.
- Scheduling validates explicit predecessor_ids separately from parent hierarchy; construction phase templates are opt-in assumptions, and missing phases never create inherited dependencies.
- Saved task durations, optimizer occupancy, daily workforce and schedule reviews use end-exclusive calendar spans; date-only values use local civil dates so approved proposals reconcile after reload.
- Task creation carries stable UUIDs through tool replay and approval retries with database ON CONFLICT DO NOTHING; callbacks await persistence before success, and approved date changes use an atomic invoker RPC under existing RLS.
- Reviewed drawing rows receive stable IDs before approval and persist in one batch; errors retain drafts, multipart audits merge, and incomplete scope remains flagged rather than silently certified.
- Costs accepts only its latest load and subscribes to estimates/tasks change notifications; estimates must remain included in the realtime publication so open Costs views update after writes.
- Multipart drawing reconciliation never merges lines within one analyzed part or across different uploaded files; across parts of one file it keeps each identity's largest per-part count, treats line IDs/tags as identity, and flags untagged merges for review, so separate identical runs are not undercounted.
- Account approval is enforced in the database (insert and email-change triggers on auth users, plus a restrictive 'Approved accounts only' policy on every public table and storage), with an app-wide guard that signs out unapproved sessions; new tables must get the same restrictive policy.
